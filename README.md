# postingttii

Локальный мультипостер для коротких видео:

- 2× TikTok
- 2× Instagram Reels
- 2× YouTube Shorts
- папка `videos/inbox` как очередь на публикацию
- OpenAI генерирует описание и хештеги
- локальная панель управления в браузере

Проект использует официальные API платформ и OAuth. Секреты и токены не коммитятся в Git.

## Instagram: две Meta App + отдельные профили Microsoft Edge (Windows)

Эта ветка основана на стабильной версии с обложками Instagram и Telegram
Studio (`fix/instagram-meta-concurrency-20261009`). Tor Browser и Tor OAuth
**не используются**. Существующие авторизации и обложки не удаляются.

- **Meta 1 · Edge (основной режим):** **любой свободный Instagram-слот 1–8**
  подключается через `INSTAGRAM_CLIENT_ID`, `INSTAGRAM_CLIENT_SECRET`,
  `INSTAGRAM_REDIRECT_URI`. Это работает и для новых аккаунтов в слотах 6–8.
- **Meta 2 · Edge (совместимость):** ранее подключённые аккаунты в слотах 6–8
  остаются со своими токенами. Второе приложение доступно опционально через
  `INSTAGRAM_CLIENT_ID_2`, `INSTAGRAM_CLIENT_SECRET_2`,
  `INSTAGRAM_REDIRECT_URI_2`.

Для каждого Instagram-слота Edge запускается с отдельным постоянным
`user-data-dir` в `data/edge_instagram_profiles/slot_N`. Повторное открытие
слота использует **тот же профиль**. При первом подключении Instagram
попросит войти и дать доступ Meta-приложению через официальный OAuth.
Вход в Edge сам по себе не означает, что приложение может публиковать:
аккаунт станет «Подключён» после успешного OAuth callback и сохранения
токена. Последующие Reels публикуются прежним способом через Meta API,
а не автоматизацией браузера.

В панели пустые слоты скрыты. Для подключения нового Instagram-аккаунта
нажмите «Подключить Instagram · Meta 1 / Edge», выберите **любой**
свободный слот от 1 до 8 и завершите вход в открывшемся Edge.
Если аккаунты уже добавлены в первое Meta-приложение, добавлять их во
второе приложение **не нужно**. После успешного OAuth они появятся
в панели и очереди публикаций. Все сохранённые обложки остаются на месте.

Важно: для обеих Meta App зарегистрируйте соответствующие **точные**
HTTPS Redirect URI. Чтобы Reels могли получать видео и обложки, установите
`PUBLIC_BASE_URL` в действующий HTTPS-домен. Если используется Cloudflare Quick
Tunnel, его адрес может измениться после перезапуска.

### Туннель только для Instagram (Media + OAuth callback)

Публично открывать локальную панель на 8765 не требуется. Запустите
основное приложение на `127.0.0.1:8765`, затем gateway:

```powershell
.\\.venv\\Scripts\\python.exe -m uvicorn media_gateway:app --host 127.0.0.1 --port 8766 --no-access-log
```

В отдельном PowerShell:

```powershell
cloudflared tunnel --url http://127.0.0.1:8766
```

У gateway разрешены только `GET/HEAD /media/{token}` и
`GET /auth/instagram/callback`; он не публикует панель управления или
API Account Manager. Задайте HTTPS-туннель в `PUBLIC_BASE_URL` и
`INSTAGRAM_REDIRECT_URI` (с путём `/auth/instagram/callback`) для
**первого** приложения. В Meta for Developers этот адрес должен быть в
списке разрешённых OAuth Redirect URIs. `INSTAGRAM_REDIRECT_URI_2`
требуется только при отдельной авторизации через второе приложение.

При переходе с прошлой Tor-ветки **не нужно удалять** `.env`, `data/` или
`videos/`. Tor-переменные, если остались в локальном `.env`, в этой версии
игнорируются.

## Instagram — шаблоны описаний из локального TXT

Автоматические Instagram-описания теперь берутся **только** из файла
`data/instagram_caption_templates.txt`, а не из OpenAI или старых встроенных
текстов. Файл содержит 13 записей из предоставленного пользователем TXT;
каждая запись отделяется строкой `---`. Тексты (включая хештеги и эмодзи)
не редактируются. Для сочетания «название видео + слот аккаунта» выбирается
стабильный шаблон.

Сам TXT не выкладывается в публичный GitHub: папка `data/` исключена из
индекса Git. Чтобы установить шаблоны на своём ПК:

1. Скачайте `instagram_caption_templates.txt` из текущего чата.
2. Поместите файл по адресу
   `C:\Users\blackpansel\Desktop\postingttii\data\instagram_caption_templates.txt`.
3. Или, если исходный файл лежит в папке Downloads, выполните:

```powershell
cd "C:\Users\blackpansel\Desktop\postingttii"
New-Item -ItemType Directory -Force ".\data" | Out-Null
Copy-Item -LiteralPath "$env:USERPROFILE\Downloads\instagram_caption_templates (1).txt" -Destination ".\data\instagram_caption_templates.txt"
```

Путь можно переопределить переменной `INSTAGRAM_CAPTION_TEMPLATES_FILE`
в `.env`. Если путь относительный, он считается от корня репозитория.

Только Instagram использует шаблоны; генерация описаний для TikTok и YouTube
не меняется. В пакетной публикации тексты Instagram больше не создаются
через OpenAI. Если TXT отсутствует либо пустой, запуск Instagram-очереди
завершается понятной ошибкой, без подстановки постороннего текста.
Проверьте, что конкретный шаблон действительно подходит ролику:
некоторые записи в исходном TXT содержат названия брендов и утверждения
о конкретных произведениях.

## Meta 2 — отдельная вкладка без ручных номеров и вход через Dolphin

В Instagram-панели переключайтесь между **Meta 1** и **Meta 2**.
Существующие аккаунты Meta 1 остаются подключёнными, их токены и история
публикаций не затрагиваются.

Для нового аккаунта выберите **Meta 2 → + Добавить Instagram через Dolphin**.
PostingTTII автоматически выделит внутренний идентификатор (начиная с 9),
покажет локальную ссылку авторизации и по возможности скопирует её.
**Откройте выбранный профиль установленного Dolphin на том же компьютере,
вставьте ссылку в адресную строку и завершите Instagram OAuth.** При
необходимости выполните обычное подтверждение входа в браузере. После
успешного callback аккаунт с его именем появится во вкладке Meta 2 и в
существующей очереди публикации через Meta API. Номера вручную не вводятся.

Приложение не открывает Edge для новых подключений Meta 2, не управляет
профилями Dolphin, прокси, отпечатками браузера и не запрашивает логины,
пароли и коды 2FA. **Автоматический выбор/запуск определённого профиля Dolphin
потребует отдельной настройки**, потому что установка Dolphin не сообщает
PostingTTII, какой профиль нужно открыть. Вход выполняется через официальный
Meta OAuth, а не через автоматическое заполнение пароля.

Счётчик хранится в `data/instagram_meta2_last_slot.txt` и не сбрасывается
при удалении аккаунтов, чтобы историю публикаций не сопоставить с другим
аккаунтом. После OAuth каждый аккаунт получает индивидуальный токен в
зашифрованном TokenStore. Лимита в восемь записей в PostingTTII больше нет,
но сохраняются ограничения Meta API и разрешения приложения.

В `.env` должны быть заполнены `INSTAGRAM_CLIENT_ID_2`,
`INSTAGRAM_CLIENT_SECRET_2`, `INSTAGRAM_REDIRECT_URI_2`.
HTTPS redirect должен точно совпадать с разрешённым OAuth Redirect URI
**второй** Meta App. Публичный Cloudflare Tunnel направляйте только на
Media Gateway, порт 8766; не открывайте интерфейс 8765 в интернет.

Обложки новых аккаунтов доступны из карточек и в `/instagram-covers`.
Meta 1, старые обложки, TXT-описания, очередь и Telegram Studio не
изменяются. Не удаляйте локальную папку `data/`. Реальный вход через
Dolphin нужно проверить на Windows.

## Telegram Studio: рекламный баннер и превью 9:16

В Telegram Studio, под загрузкой фоновых видео, появился блок
**«Оформление Reels · баннер и кружок»**. В нём:

- вертикальная миниатюра **9:16** с одним из активных MP4-фонов и
  примером последнего скачанного Telegram-кружка (если оригиналов ещё нет,
  показывается заглушка);
- размер круга **1040 px по умолчанию**, с регулировкой **760–1080 px**,
  вместо прежних жёстко заданных 980 px;
- **хромакей только для рекламного баннера** (PNG/JPG/WEBP/MP4/WebM):
  **Telegram-кружок и видеофоны не затрагиваются**. Встроенная пипетка берёт
  цвет прямо с загруженного баннера или остановленного кадра видео-баннера.
  Можно выбрать другой цвет вручную (формат #RRGGBB), настроить
  чувствительность и мягкость краёв. В браузере показано приблизительное
  удаление цвета, а при реальном рендере FFmpeg chromakey применяется
  исключительно к входу баннера `[2:v]`. Без баннера хромакей не применяется.
  В прежних шаблонах сохраняются числовые настройки и зелёный по умолчанию
  #00FF00, но смысл опции теперь относится только к баннеру;
- необязательный рекламный баннер **PNG/JPG/WEBP (до 10 МБ) или
  MP4/WebM (до 100 МБ, длина до 10 минут)**, опция включения/выключения,
  регулировка ширины 100–1080 px, перемещение по миниатюре мышью или
  касанием; позиции сохраняются в пикселях **1080×1920**. Видео-баннер
  воспроизводится в превью и повторяется до конца рендера. В итоговом ролике
  используется исходный звук Telegram-кружка; звуковая дорожка баннера
  **не добавляется**. Видеофайлы проверяются через FFprobe;
- кнопки сброса позиции и удаления баннера.

Оформление сохраняется в существующем
`data/telegram_studio/config.json` (поле `render_design`), загруженный
баннер хранится в `data/telegram_studio/banners/`.
Оригинальные кружки и MP4-фоны не изменяются. На момент запуска
**«Скачать и смонтировать»** настройки фиксируются на всю партию.
Готовые ролики по-прежнему попадают в общую папку
`videos/inbox` для последующей публикации. Во время рендера
замена баннера и редактирование настроек заблокированы сервером.

Для загрузки изображений требуется Pillow (добавлен в
`requirements.txt`; устанавливается через `start.ps1`).
Реальное положение баннера и работа с альфа-каналом проверены на
тестовых фильтрах FFmpeg. Финальный UI на компьютере пользователя
пока требует проверки.

## Два независимых шаблона монтажа (Telegram и Instagram)

В Telegram Studio → **«✦ Конструктор оформления Reels»** имеются две вкладки:

**Telegram · кружки**
- Перемещайте кружок непосредственно мышкой по 9:16-миниатюре и меняйте его диаметр
  за белый маркер (или ползунком, 400–1080 px). Начальное расположение
  сохраняет привычный вид: 1040 px, X=20, Y=90.
- Выбирайте **«🔀 Смешивать фоны»** или **«▣ Один фон»**. Смешивание проходит
  по всем включённым MP4 фонам, чередуя их между следующими кружками
  (без повтора подряд, если фонов больше одного). Один фон использует
  строго выбранный активный файл. При единственном активном фоне смешивать
  нечего — он и будет использоваться во всех роликах.
- Обложки/баннеры PNG/JPG/WebP/MP4/WebM, хромакей, положение и размер
  баннера сохраняют прежнюю работу. Эти данные остаются в
  `data/telegram_studio/config.json`.

**Instagram · видео**
- Отдельная миниатюра 9:16 для **обычного Instagram-видео** (не кружка):
  мышкой меняются X/Y и размер видео (также доступен ползунок ширины).
  Перед рендером можно загрузить своё локальное видео для предпросмотра:
  этот файл не включается в очередь и не заменяет исходники.
- **Прозрачность обычного видео: 10–100%** над фоном, аудиодорожка
  оригинального видео сохраняется.
- **4 фоновых режима:** «🔀 Смешивать» (все включённые MP4 фоны по очереди),
  «▣ Один фон» (строго выбранный MP4), «◌ Размытие» (размытая копия
  исходного видео), «▯ Без фона» (тёмный холст без отдельного
  фонового клипа). Если в режиме смешивания нет доступных фонов,
  обработка автоматически использует размытие вместо ошибки.
- Настройки Instagram сохраняются **отдельно от Telegram** в
  `data/instagram_studio/sources.json` (поле `layout`). Добавленные
  ранее аккаунты, скачанные файлы, история обработанных видео и публикации
  не перезаписываются.

Выбор одного фона действует только на соответствующую вкладку.
В Telegram и Instagram можно установить **разные** режимы и фоновые
видео. Настройки фиксируются при старте каждой задачи монтажа, поэтому
изменения не влияют на уже запущенную очередь. Реальная публикация
по-прежнему использует основную очередь PostingTTII.

## Instagram Analytics — общая статистика Meta 1 / Meta 2

В главной панели PostingTTII появилась кнопка **«📊 Статистика Instagram»**.
Адрес на локальном компьютере: http://127.0.0.1:8765/instagram-stats.

- Профили берутся из существующего зашифрованного TokenStore; показываются все подключённые Meta 1 и Meta 2, без удалённых аккаунтов.
- Доступны подписчики, общее количество публикаций, до 50 последних Reels на аккаунт, лайки, комментарии, ссылки на ролики и рейтинг лучших.
- Просмотры Reels запрашиваются через Instagram Insights для последних 30 Reels на аккаунт. Недоступные метрики показываются прочерком, а не нулём; суммы учитывают только полученные значения.
- История подписчиков сохраняется в data/instagram_stats.json. График и рост строятся с момента первого успешного замера; изменения просмотров сравниваются с предыдущим замером. Файл исключён через .gitignore и не содержит OAuth-токенов.
- Автоматическое обновление примерно каждые 30 минут, пока PostingTTII запущен, либо вручную. Когда ПК выключен, история не записывается.
- Дополнительное разрешение Meta: существующие токены могут не содержать instagram_business_manage_insights. При ограничении появится кнопка **«Подключить Insights»**, которая копирует локальную ссылку официальной OAuth авторизации для исходного аккаунта Meta1/Meta2. Откройте её в браузере с нужным Instagram. Публикация через Meta не затрагивается при ошибке авторизации.

Технически: GET /api/instagram-stats возвращает кешированную статистику, POST /api/instagram-stats/refresh запускает обновление в фоне. Оба API только на localhost, публичный Media Gateway на 8766 не открывает интерфейс.

## Папки публикации и отдельные фоны для Instagram-аккаунтов

На главной странице PostingTTII появился блок **«📁 Папки и фоны аккаунтов»**. Он не изменяет авторизацию Instagram Meta 1/Meta 2 и не влияет на доступ к Meta API.

**Добавление папки:** нажми «📂 Выбрать на ПК», в Windows откроется системный выбор директории (если он недоступен, введи полный путь вручную). Укажи название папки, нажми «Сохранить папку». Папка должна уже существовать на компьютере.

**Публикация:** над настройками очереди выбирается папка, откуда читать видео. Режим **«Папки аккаунтов (автоматически)»** берёт ролики по отдельности из привязанной папки каждого отмеченного Instagram-аккаунта. В этом режиме следует оставлять отмеченными только Instagram-аккаунты; YouTube и TikTok поддерживаются в обычном режиме выбора одной папки. Во всех режимах прежний контроль дублей по SHA-256 сохраняется. После подтверждённой публикации файл сразу перемещается из исходной папки в архив: обычная videos/inbox → videos/posted, пользовательская папка → подпапка posted внутри неё. Исходники не удаляются при ошибке публикации.

**Монтаж:** в Telegram Studio, в секции «Автомонтаж», и в Instagram Studio, в секции «Скачать и смонтировать Instagram», появились два новых поля: «Папка готовых Reels» и «Для какого Instagram-аккаунта монтировать». Если у аккаунта зарегистрирована папка, выбирай «Папка выбранного аккаунта». Можно также выбрать другую папку из списка. Если у выбранного аккаунта настроен индивидуальный активный MP4-фон, он используется в рендере вместо общего режима смешивания/фона. Для Telegram-кружков и обычных Instagram-видео фон можно задать независимо в карточке аккаунта на главной странице.

**Повторный рендер:** история обработанных оригиналов разделяется между аккаунтами и нестандартными директориями, чтобы для другого аккаунта или папки можно было смонтировать тот же исходник с другим фоном. Стандартная история videos/inbox сохраняется.

Все привязки хранятся в data/video_folder_settings.json, вне Git. Пользовательские каталоги и оригиналы никак не загружаются на сервер GitHub. Папки разрешены только после добавления в локальном UI. API папок доступен только через localhost PostingTTII:8765, не через публичный Media Gateway.

## Telegram Studio: изображения в фонах и выбор типа Telegram-видео

В разделе **«02 / Фоны: видео и фото»** доступны MP4, JPG/JPEG, PNG и WebP.
Изображения проверяются Pillow, корректно поворачиваются по EXIF, объединяются с тёмной подложкой при прозрачности и сохраняются как JPEG в каталоге data/telegram_studio/backgrounds.
Ограничение для изображения — 25 МБ и до 60 миллионов пикселей. MP4-фоны продолжат работать как прежде (максимум 1 ГБ).
Фотография занимает вертикальный холст 1080×1920 без движения на всю длительность ролика, MP4 повторяется по кругу. При смешивании можно использовать фото и видео в одной очереди.
Предпросмотр и списки фонов Telegram Studio и Instagram Studio показывают оба формата, а индивидуальный фон Instagram-аккаунта может быть статичной фотографией.

В разделе **«01 / Источники»** добавлен переключатель:

- **◉ Только кружки (видеосообщения):** прежний режим по умолчанию. Из Telegram-каналов читаются только video_note, FFmpeg накладывает круг на фон с выбранным Telegram-баннером.
- **▯ Только обычные видео:** из Telegram-каналов читаются обычные видеосообщения и документы с MIME video/*, но не кружки. Для этих видео используется *прямоугольный* вертикальный шаблон из вкладки «Instagram · видео» без круглой маски, с оригинальным звуком. Фон берётся из выбранного списка Telegram Studio; баннер и хромакей Telegram-кружков в этом режиме не применяются.

Выбранный тип действует на **все Telegram-каналы в одном запуске**, сохраняется в браузере и передаётся в `/api/telegram-studio/run` как `media_mode=circles|videos`.
Оригиналы обычных видео хранятся отдельно в data/telegram_studio/originals/regular, а готовые Reels имеют префикс `tgvideo_` (в отличие от `tg_` у кружков).
Истории обработанных кружков и обычных Telegram-видео разделены; существующие каналы, публикации и результаты сохраняются.

Остальные настройки (папка рендера, назначенный Instagram-аккаунт, его фон, интервал и выбор фона) продолжают работать. Пробный запуск рекомендуется сначала провести с лимитом 1–2 ролика на канал.

## Последний готовый рендер и общий рекламный баннер

В Telegram Studio перед конструктором появился отдельный блок **«▶ Последние готовые ролики»** с режимами **«Telegram · кружки»**, **«Telegram · видео»** и **«Instagram · видео»**. Он показывает **реальный результат FFmpeg**, а не исходное Telegram-видеосообщение и не макет: миниатюру, имя файла, время готовности, пометку о применении баннера и кнопку воспроизведения MP4.

После удачного рендера путь к ролику и факт наложения баннера сохраняются в `data/telegram_studio/config.json` (или в `data/instagram_studio/sources.json` для Instagram Studio) и остаются доступны после перезапуска. Старые результаты из стандартной `videos/inbox` распознаются по префиксам `tg_`, `tgvideo_`, `ig_`, но статус баннера для них неизвестен. Пользовательские выходные папки находятся по сохранённым путям. Отдельные API `GET /api/telegram-studio/last-render?mode=circles|videos|instagram`, `/last-render/video` и `/last-render/poster` отдают последний MP4 и созданную из него миниатюру; исходные ролики не подменяют её.

**Баннер и хромакей применяются к готовым роликам всех трёх режимов**, если опция «Добавить рекламный баннер» включена и файл баннера загружен в Telegram Studio. Это включает круглый рендер Telegram, прямоугольный рендер обычных Telegram-видео и рендер импортированных Instagram-видео. Используется одна сохранённая позиция баннера, размер и выбранный цвет chromakey. Для обычных видео рекламный баннер теперь также показан в конструкторе Instagram, в том числе приблизительное удаление цвета на превью. Аудио остаётся только из исходного видео; звук баннера не добавляется.

При включённом баннере без загруженного файла запуск возвращает понятную ошибку, а не silently рендерит без баннера. Видео, созданные до изменения, **не перезаписываются автоматически** — для получения баннера потребуется рендер новых исходников. Старые пути Meta 1/Meta 2, очередь публикации, фоны и исходники сохранены.

## Параллельные публикации Meta и независимые баннеры двух шаблонов

**Пакетная публикация:** в существующей очереди PostingTTII для одной волны запускаются публикации на все выбранные Instagram-аккаунты через `asyncio.gather`. Раньше глобальный `INSTAGRAM_META_SEMAPHORE = asyncio.Semaphore(1)` последовательно пропускал их через один обработчик и замедлял публикацию. Он заменён на **отдельный `asyncio.Lock` для каждого Instagram slot**, поэтому разные аккаунты теперь могут публиковать параллельно, а одновременные операции в один и тот же аккаунт запрещены. Защита от дублей, индивидуальные ограничения Meta, ожидание между первым и вторым роликом (например 60–160 секунд), пауза между волнами (например 22–28 минут) и очередь после рестарта сохраняются. На слабом туннеле скорость и ошибки Meta API всё равно могут ограничивать результат. **Активную очередь не нужно прерывать ради этой настройки; новый алгоритм действует после перезапуска.**

**Telegram Studio · кружки:** рекламный баннер управляется своим загруженным изображением/видео и параметрами `RenderDesign` как раньше; теперь на кадре 9:16 можно перемещать его мышкой и **масштабировать за правый нижний угол** (ползунок ширины тоже работает).

**Instagram Studio · обычные видео:** добавлена независимая загрузка своего баннера через `/api/telegram-studio/instagram/banner` (PNG/JPG/WebP/MP4/WebM), отдельное включение, положение `banner_x`, `banner_y` и ширина `banner_width` в `InstagramLayout`. На миниатюре есть своя рамка перетаскивания и маркер масштабирования. По умолчанию старый шаблон, не содержащий этих полей, **наследует** прежний баннер кружков и его координаты, пока не добавлен свой. После самостоятельного изменения можно использовать разный баннер/размер/позицию для кружков и обычных видео.

Обычные Telegram-видео используют видео-шаблон Instagram Studio, а Telegram-кружки сохраняют прежний собственный баннер. Импортируемые Instagram-видео тоже используют отдельный видео-баннер. Параметры хромакея (цвет/чувствительность/мягкость) по-прежнему берутся из настроек Telegram Studio — хромакей применяется к **каждому баннеру отдельно**, а не к кадрам ролика.

Исправлено сохранение ограниченных координат баннеров после загрузки их фактических пропорций, чтобы результат рендера совпадал с видимым на миниатюре. Публикации, аккаунты Meta1/Meta2, прокси, видеоисточники и уже созданные MP4 не изменяются. Для уже готового MP4 потребуется новый рендер, если нужен иной баннер.

## Instagram · браузер: отдельная публикация без Meta API

Новая локальная вкладка **«🌐 Instagram · браузер»** открывается с главной страницы или напрямую по адресу http://127.0.0.1:8765/instagram-browser.

- Новый режим не изменяет и не использует уже подключённые Meta 1 / Meta 2 аккаунты, токены, очереди публикаций или Cloudflare Tunnel.
- Аккаунты браузерного режима добавляются отдельно только по Instagram username. Вход выполняется **вручную** в отдельном видимом профиле Microsoft Edge. Пароли Instagram приложение не запрашивает и не хранит.
- Для каждого аккаунта создаётся отдельная папка браузера в `data/browser_instagram/profiles/<id>`; сессия сохраняется на локальном компьютере. Информация об аккаунтах находится отдельно в `data/browser_instagram/accounts.enc`, зашифрована существующим Fernet-ключом TokenStore. В Git данные не попадают.
- Существующие сессии Dolphin / Meta OAuth автоматически не импортируются; необходимо войти в каждый браузерный профиль отдельно.
- Можно выбрать один или несколько браузерных аккаунтов, зарегистрированную папку `videos/inbox` либо другую папку из PostingTTII, один или несколько локальных MP4/MOV и общую подпись. Запуск требует явной галочки подтверждения.
- Приложение выполняет один пост за другим через браузерный UI Instagram (Playwright). Задание ограничено 25 выбранными публикациями. Встроенный статус показывает попытки/успех/ошибку.
- При запросах дополнительных проверок Instagram пользователь проходит их вручную. Приложение не решает CAPTCHA и не обходит верификацию. Если после нажатия Share нельзя достоверно подтвердить результат, очередь останавливается с `needs_review` — **никакой автоматической повторной отправки**, чтобы не создавать дубликаты.
- Публикация через веб-интерфейс Instagram зависит от актуальной разметки и может потребовать доработки при изменениях сайта. Её не следует считать полностью протестированной на реальных аккаунтах до пробной отправки одного ролика.
- У браузерного режима нет расписания на будущие дни; требуется локальный запущенный PostingTTII, открытое окно Edge и явный запуск пользователем.

**Прокси для своих браузерных профилей:** необязательный HTTP/HTTPS или SOCKS5-прокси можно указать при добавлении браузерного аккаунта, а позже — изменить или удалить через кнопку «⚙ Прокси» у его карточки. Поддерживаемые форматы: `host:port`, `host:port:login:password`, `http://login:password@host:port`, `https://host:port` и `socks5://host:port` (для SOCKS5 авторизация логином/паролем через Edge Playwright не поддерживается). Некоторые резидентские провайдеры используют логин с параметрами зоны — копируй его полностью. Пароли прокси хранятся в `data/browser_instagram/accounts.enc` под локальным Fernet-ключом и не выдаются в API статистики или интерфейс.

Кнопка **«Проверить прокси и IP»** направляет запрос к `https://api.ipify.org?format=json` именно через указанный прокси и показывает внешний IP и задержку. В карточке профиля можно проверить сохранённый прокси, не вводя пароль заново. Проверка связи с ipify сама по себе не гарантирует доступность Instagram или успешную публикацию. После смены прокси требуется закрыть и снова открыть Edge-профиль (во время публикации и при открытом окне изменение запрещено). Для SOCKS5-тестов установи обновлённые зависимости `httpx[socks]`: `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`.

**Примечание:** обычная настройка своего прокси не отключает защитные проверки Instagram. При запросе подтверждения личности или входа пользователь проходит их вручную; скрипт не обходит ограничения платформы.

При запуске Python через `python -m app.main` Edge должен быть установлен на ПК. Playwright уже есть в `requirements.txt`. Если зависимости не установлены, выполнить `pip install -r requirements.txt` в виртуальном окружении.

## Исправление браузерной публикации: этапы ошибок и открытие Edge

Если отправка в Instagram через Edge остановилась, вкладка `Instagram · браузер` теперь показывает **этап сбоя** (подключение Edge, открытие Instagram, вход, кнопка «Создать», выбор файла, «Далее», описание, Share или ожидание подтверждения). Вместо неопределённого «Некорректный ответ сервера» UI сообщает HTTP-код и безопасное сообщение; необычные ошибки записываются в консоль PostingTTII с типом исключения и этапом, без полного текста Playwright, который может содержать данные прокси.

Закрытое пользователем окно Edge удаляется из живого реестра сессий при событии `context.close`. Следующее подключение создаёт новый браузерный контекст с прежним локальным профилем и сохранённым логином.

Повторное нажатие «Открыть Edge», когда профиль уже запущен (особенно при загрузке ролика или после неудачного рендера), **только выводит окно на передний план и не выполняет `goto`**. Это предотвращает случайное прерывание загрузки и сохраняет страницу с ошибкой для ручной проверки. Первое открытие закрытого профиля по-прежнему переходит к `instagram.com`; при неудаче сети возвращается JSON HTTP 502 с рекомендацией проверить соединение/прокси.

При ошибке конкретного шага очередь останавливается без повторной отправки. Если Share был нажат, но Instagram не показал подтверждение, статус `needs_review` означает **проверить публикацию вручную, прежде чем запускать её снова**. Старый браузерный профиль и прокси не удаляются.

В регрессионных тестах проверяется сохранение страницы во время загрузки и после ошибки, закрытие Edge, безопасные коды ошибок, этап загрузки видео и отсутствие передачи паролей прокси в интерфейс. Реальный end-to-end тест на Instagram требует вручную авторизованный профиль пользователя и не запускался в репозитории.

### Диагностика «Нет ответа через прокси»

Проверка собственного прокси в браузерной вкладке PostingTTII возвращает отдельные категории вместо единого «Нет ответа»:

- `auth_required` — HTTP 407, проверь логин и пароль.
- `access_denied` — HTTP 401/403, проверь авторизацию, разрешённые IP и активность зоны у провайдера.
- `connect_timeout` — прокси не устанавливает соединение вовремя.
- `read_timeout` — соединение установлено, но ответ задерживается.
- `connect_error` — соединение не установлено, проверь адрес, порт и протокол.
- `proxy_rejected` — прокси отклонил соединение.
- `bad_ip_response` — проверочный сервис прислал ответ без корректного IP.

Ответы не содержат пароль прокси или исходный текст ошибок HTTPX. Успешная проверка показывает внешний IP и задержку HTTPS-запроса к `api.ipify.org`, но сама по себе не гарантирует доступность Instagram. Параметры зоны (например, `country-XX`) задаёт провайдер: проверь, поддерживается ли выбранная страна.

### Дополнительные форматы прокси для браузера

Парсер прокси теперь принимает записи резидентских провайдеров с логином и паролем в обоих вариантах:
- `198.51.100.15:5000:login-country-af:password`
- `http://198.51.100.15:5000:login-country-af:password`
- `http://login-country-af:password@198.51.100.15:5000`
В полях `host:port:user:password` пароль может содержать двоеточие, `@`, `#`, `?` или `%`; приложение безопасно кодирует их при подготовке адреса для HTTPX и Playwright. Для неверного формата возвращается инструкция без раскрытия пользовательского пароля.
Старые записи без схемы, стандартные HTTP(S) URL и SOCKS5 без логина/пароля продолжают поддерживаться. Прокси не проверяется до нажатия пользователем «Проверить прокси и IP».

### Расшифровка отказов HTTPS CONNECT

При проверке резидентского прокси через HTTPS `httpx.ProxyError` может означать разные ответы шлюза (`407`, `403`, `429`, `502` и др.). Статус находится в тексте исключения HTTPX, а не в обычном `response.status_code`; теперь проверка извлекает только безопасный начальный HTTP-код и выводит отдельную категорию:

- `407` → `auth_required`: проверь логин, пароль и настройки авторизации у провайдера.
- `401/403` → `access_denied`: доступ запрещён прокси-шлюзом, проверь правила доступа.
- `429` → `rate_limited`: ограничение скорости/количества запросов.
- `500/502/503/504` → `upstream_failure`: ошибка самого прокси-шлюза или его связи с адресатом.
- Неизвестный статус → `proxy_rejected`: общий отказ без исходного текста, чтобы не раскрыть прокси-секреты.

Проверено на тестовом локальном HTTP-прокси: HTTPX 0.28.1 выдаёт `ProxyError('407 Proxy Authentication Required')`, аналогично для 403 и 502. Добавлены тесты на соответствие категорий и отсутствие секретов в результатах. Никаких автоматических изменений схемы/логина/пароля прокси не выполняется.


## Очистка папок после публикации Instagram

После успешного и подтверждённого размещения Reel файл **сразу исчезает из
папки отправки** и перемещается в локальный `posted`: из `videos/inbox` в
`videos/posted`, либо в `posted` внутри выбранной пользовательской папки.
Это перемещение, а не безвозвратное удаление с диска.

- В планировщике Meta очистка выполняется после подтверждённой публикации
  каждого ролика. Публичная временная ссылка Meta остаётся рабочей: запросы
  перенаправляются на уже перемещённый MP4.
- Обычная публикация через Meta тоже убирает файл, если все выбранные
  аккаунты/платформы завершились успешно.
- В браузерном постинге Instagram, если один файл выбрали для нескольких
  аккаунтов, он перемещается лишь когда все отправки этого файла подтверждены.
- При неудаче или неопределённом результате видео остаётся в исходной папке.
- Если Windows ещё использует файл, очередь Meta повторит перемещение
  через 30 секунд (максимум 12 попыток). Ошибка очистки не считается ошибкой
  публикации.

### Telegram: строгий выбор типа

В меню Telegram Studio `Только кружки` означает только сообщения типа
`video_note`, которые монтируются круглым шаблоном и сохраняются как `tg_*.mp4`.
`Только видео` означает обычные видео/видеофайлы, без `video_note`.
Они монтируются прямоугольным шаблоном и сохраняются как `tgvideo_*.mp4`.
Выбор проверяется и при поиске сообщений, и непосредственно перед скачиванием.

Тесты: `.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_instagram_upload_cleanup.py"`
и `-p "test_telegram_studio_media_types.py"`.


### Скачанные с Instagram исходники

Instagram Studio автоматически удаляет временный скачанный оригинал из
`data/telegram_studio/instagram` после того, как готовый MP4 прошёл проверку
и оказался в выбранной папке рендера. При неудачном монтаже скачанный файл
остаётся для повторной попытки. Если исходник и готовый файл расположены
по одному пути, удаление запрещено. Готовые Reels не удаляются.
Для повторных уже готовых файлов и дублей временные остатки также очищаются.
