# Telegram Studio

Отдельная вкладка PostingTTII: http://127.0.0.1:8765/telegram-studio

## Подготовка Windows

1. Установите FFmpeg и FFprobe и добавьте их в PATH. Проверьте `ffmpeg -version` и `ffprobe -version`.
2. Получите Telegram API ID и API Hash на https://my.telegram.org (API development tools).
3. Добавьте в локальный `.env`:
   ```env
   TG_API_ID=YOUR_ID
   TG_API_HASH=YOUR_HASH
   ```
4. Запустите проект обычным `./start.ps1` в PowerShell.
5. Откройте вкладку Telegram Studio. Авторизуйте свой Telegram, добавьте публичные каналы и загрузите MP4-фоны.
6. Нажмите «Скачать и смонтировать». Результаты появятся в `videos/inbox` и в основной очереди публикации.

## Ограничения

- Выбор «Только кружки» обрабатывает исключительно Telegram video notes; «Только видео» — исключительно обычные видео/видеофайлы. Для каждого режима отдельные папки оригиналов и шаблоны.
- Для закрытых каналов нужен доступ авторизованного аккаунта; ввод через публичный username поддерживается, invite links пока нет.
- Лимит в форме означает количество последних сообщений на канал, а не количество кружков.
- Исходный файл скачивается без дополнительных водяных знаков загрузчиков; уже встроенные в исходник знаки не удаляются.
- Работает по нажатию кнопки. Периодический автоматический мониторинг пока не реализован.
- Первая версия не тестировалась на реальных каналах и на Windows. Не сливайте `.env`, session-файлы и коды Telegram в GitHub.
- Используйте видео, на которые есть разрешение для повторной публикации.

## Оформление Telegram-кружка

В шаблоне «Telegram · кружки» доступна обводка (цвет и толщина),
отдельная полоса воспроизведения с динамическим заполнением и
перетаскиваемый таймкод текущей и общей длительности в формате мм:сс.
Полосу можно перетаскивать и менять по ширине правым маркером.
Размер и положение кружка остаются внутри кадра 1080×1920.

На выходе можно выбрать 30 или 60 FPS. По желанию включается
интерполяция движения: это ресурсоёмкая операция, создающая новые кадры.
Видео- и фото-баннеры плавно появляются за 0,3 секунды.

Эти параметры сохраняются в существующем дизайн-шаблоне Telegram Studio.
Для окончательной проверки открой последний отрендеренный MP4 в блоке
«Последние готовые ролики». Проверены отдельные фильтры FFmpeg;
полный запуск на Windows не выполнялся.

Изменения: feature/studio-circle-progress-20261025 (основана на
fix/browser-proxy-connect-rejection-status-20261021).
Тесты: python -m unittest tests.test_studio_circle_progress


## Выбор типа скачивания и шаблона

В Telegram Studio выпадающий список типа сообщений и вкладки конструктора
теперь **синхронизированы**: «Telegram · кружки» = только настоящие круглые
`video_note` сообщения; «Обычные видео · Telegram / Instagram» = только
обычные видео (без `video_note`). При переключении вкладки автоматически
меняется тип скачивания, а кнопка запуска показывает его явно. Видеосообщения
также распознаются по атрибуту `round_message` Telegram.

Если канал не содержит сообщений требуемого типа, приложение выводит запись
об отсутствии подходящих медиа, а не скачивает видео другого формата.
Ранее скачанные файлы `tgvideo_*.mp4` из папки очереди автоматически не
удаляются: они могли быть опубликованы или выбраны пользователем.

## FFmpeg на Windows: Fontconfig и таймкод

Начиная с исправления 2026-10-25, таймкод на Windows использует
установленный на этом компьютере Arial/Segoe UI/Tahoma/Verdana напрямую:
приложение помещает рабочую локальную копию шрифта в
`data/telegram_studio/_timecode_render_font.ttf` и передаёт FFmpeg
`drawtext=fontfile=...`. Никаких дополнительных установок Fontconfig
или правок переменных среды не требуется.

Если конкретная Windows-сборка FFmpeg всё равно аварийно завершается
с ошибкой Fontconfig или кодом `3221225477` (`0xC0000005`),
рендер автоматически **один раз** повторяется без таймкода. Обводка,
прогресс-бар, фон и баннер остаются включёнными, а в статусе появляется
предупреждение. Оригиналы Telegram не удаляются. В конструкторе всегда
можно снять галочку «Показывать таймкод», чтобы сразу использовать
вариант без шрифтов.

Если и повторный рендер не проходит, приложение выводит реальный stderr
FFmpeg для диагностики; оно не считает неготовый MP4 опубликованным.


## Свободное положение баннера и качество Reels

В конструкторе обоих шаблонов (Telegram-кружки и обычное видео) можно
перетащить рекламный баннер за границы 9:16. Координаты **X/Y** допускают
отрицательные значения (X от -2160 до 2160, Y от -3840 до 3840).
FFmpeg обрезает часть баннера, вышедшую за пределы 1080×1920. Если баннер
исчез полностью, его можно вернуть через поля X/Y или кнопку «Сбросить
позицию». Настройки сохраняются независимо для каждого шаблона.

Доступны три режима качества:

- **Стандартное**: прежняя фильтрация (без коррекции), H.264 medium,
  CRF 18 для кружков и CRF 19 для обычных видео;
- **Улучшенное** (по умолчанию): бережное шумоподавление, лёгкая коррекция
  цвета и резкости, H.264 slow, CRF 17, H.264 fast (быстрее прежнего slow);
- **Максимальное**: более интенсивная обработка, H.264 slow, CRF 16,
  ограничение пикового битрейта 16 Мбит/с для совместимого MP4,
  H.264 medium вместо slow (приблизительно то же качество CRF 16,
  но обычно больший размер файла и существенно меньше нагрузка).

Все режимы сохраняют исходный звук с кодированием AAC и вертикальный кадр
1080×1920. Режим «Максимальное» требует больше времени на компьютере.
FFmpeg-обработка повышает качество технического файла, но не создаёт
оригинальность контента и не гарантирует рекомендации Instagram.
Для рекомендаций важны собственный творческий вклад, интерес зрителя
и соблюдение правил платформы.

### Если второй кружок рендерится долго

Режимы «Улучшенное» и «Максимальное» раньше применяли H.264 `slow`,
который долго кодирует 60 FPS. Теперь `enhanced` использует `fast`,
а `maximum` — `medium` при прежних CRF 17/16. Для ускорения ещё
можно выбрать **30 FPS**, выключить интерполяцию движения и оставить
«Улучшенное» качество. Эти изменения применяются только к новым
рендерам после перезапуска приложения и не удаляют готовые ролики.

В журнале Uvicorn циклические `GET /status 200 OK` — это запросы
браузера на обновление интерфейса, а не кадры прогресса FFmpeg. Чтобы
отличить кодирование от зависания, в PowerShell можно дважды выполнить
`Get-Process ffmpeg -ErrorAction SilentlyContinue | Select-Object Id,CPU,StartTime`.
Рост CPU между проверками означает, что процесс продолжает работать.


## Второй шаблон кружков: белый бегущий блик + загрузка

В конструкторе Telegram-кружков выбери **Оформление кружка**:

- **Шаблон 1** — прежняя обводка, стандартный прогресс и опциональный
  таймкод; код рендера и прежние сохранённые настройки не меняются.
- **Шаблон 2** — те же фон, кружок, белая обводка, расположение и баннер.
  По краю рамки спокойно вращается **один белый сегмент** (без неона,
  голубого свечения, дополнительных точек и частиц). Внизу — обычный
  прогресс загрузки: серо-белый трек и белое заполнение слева направо.
  Времени нет даже при включённом старом переключателе таймкода.

**Последовательность вступления только для второго шаблона:**
сначала приблизительно 0,38 секунды показывается **только фон**.
Затем кружок с белой рамкой, бегущий сегмент, нижний прогресс
и рекламный баннер постепенно появляются за 0,28 секунды.
Звук оригинального Telegram-видео не обрезается.

Оба варианта сохраняются отдельно в `render_design_presets` в
`data/telegram_studio/config.json`. Переключатель шаблона не меняет
тип скачивания: по-прежнему скачиваются **только кружки** в режиме кружков.
Второй стиль применится к новым рендерам после выбора и сохранения.

Вращающийся белый сегмент кэшируется в PNG
`data/telegram_studio/orbit_assets/white_sweep_v3_*.png`, затем
FFmpeg вращает его на прозрачном слое. Данный эффект не требует
Fontconfig. Рендер второго шаблона не использует `drawtext`.

Проверка на Windows:
`\.\.venv\\Scripts\\python.exe -m unittest discover -s tests -p "test_circle_orbit_dots_template.py"`.
